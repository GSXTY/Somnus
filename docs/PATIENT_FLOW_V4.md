# 患者呼吸流量：暂停 / 低通气候选 v4

## 本轮修正

2026-11-09，使用者明确更正：当前 YA70 CSV 的“流量”就是患者呼吸流量，单位 L/min。本项目按这个输入含义实施本轮优化，不再要求先重建患者流量，也不从该通道再减漏气。

新记录元数据通过 `flow_semantics` 保存 `role=patient_respiratory_flow`、`confirmation=user` 及更正日期。确认数据含义与确认精密采样时钟是两件事：CSV 的重复秒时间戳仍按原样保留，不因这次更正而假设统一50Hz或250ms分组时钟。旧版本自动快照中的“机器总流量/未验证Patient Flow”是历史假设，原始证据不改写；本说明取代其对当前输入的解释。

实现为独立 `profile=patient_flow_v4`，通过现有单一“检测方案”手动选择。按使用者后续要求，页面默认切回动态基线优化v3；保留现有v3首次初始化参数：去背景绝对值法、8秒窗口、10秒最短持续。v4仍可手动选择，其自身默认5秒窗口、固定10秒持续；本次仅切换页面默认方案，不改任何算法或历史事件。同一页面内明确选择过的方法、窗口和持续时间仍按既有机制在方案切换时保留。原事件库和旧批次保留，仅显示曲线不会扫描或保存候选。

本轮交付版本：`patient-flow-v4-experimental-v2`。`v1`仅为本轮内部实现中间态；v2已收紧源秒持续佐证和长事件后参考衔接，不作为先前默认v3的同版本改写。

## 新方案的数值与时间规则

- 直接读取完整 CSV 流量行，按原始源秒与有效状态分组。幅度代理为每源秒 `mean(abs(patient_flow))`，主窗口对完整源秒等权平均；单位L/min，不再除以2，不去均值或自动去背景。它是可解释的幅度代理，尚未验证等价于临床评分的逐呼吸峰值变化。
- 窗口1～10秒，默认5秒；最短持续固定10秒。暂停起始配置是剩余幅度≤10%，低通气起始配置是≤70%。这两组幅度比例是本方案的工程起点，不宣称复刻厂商阈值，也不因量化代理相似而直接作临床确认。
- 参考来自此前120源秒内、至少30个可用历史秒的60分位，明确使用 `numpy.quantile(method=linear)`，排除当前触发样本；主窗与1秒幅度分别有对应参考。怀疑持续下降时冻结，避免下降本身拉低门限。事件期间不改写过去的参考曲线。
- 两类候选都要求实际源秒幅度证据持续达到10秒，主窗另作佐证。对低通气在触发前已观察的短缓冲内按冻结参考核对起点，不能固定按窗口长度向前挪。9秒真实下降不能只因5秒窗口拖尾被凑成10秒低通气；小峰会中断连续源秒达标，当前方案采取保守处理。
- 同一个尚未充分恢复的减弱过程互斥输出：若有达到时长、且有主窗支持的暂停核心，输出暂停候选；否则检查足时长低通气段。短暂停核心不达标时，不因此放弃低通气回退。完整减弱过程、各核心、肩部和互斥策略保留在数值证据中，不将肩部自动额外算作低通气。
- 两路幅度充分恢复并持续两个有效源秒后关闭过程。长过程后的有效参考沿用与年龄在证据中标明，直到新历史参考足够；数据缺失、无效秒和状态/模式变化使参考失效，不能跨段拼接事件。
- `threshold_met_at` 表示当时证据已达到门限；`finalized_at` 表示恢复或截断后最终结果实际形成的时刻。不得用事后结果的起点或达标时刻冒充实际在线报警时间。
- 压力、漏气保留供联合复核；既不从患者流量相减，也不凭压力脉动区分OA/CA。无合格参考的初始区间、质量缺失区间属于未知，不能当作正常呼吸。

输出为“呼吸暂停候选”“低通气候选”，另有独立数据质量提示，不加入OA/CA分类或AHI。低通气尚无同步血氧下降/觉醒支持；此实现并非完整临床低通气评分。血氧、睡眠状态等字段即使出现在未来CSV，也需要先验证含义、时间与质量后才能参与判定。

## 具体参考了 OSCAR 哪些地方

| 项目 | OSCAR 2.1.1 源码行为 | 本方案的采用方式与差别 |
|---|---|---|
| 参考幅度的60分位思路 | `FlowParser::flagUserEvents` 将呼吸正负峰绝对值组成集合，取约60分位，形成用户标记门限 | 借鉴稳健参考的分位数思路；改成过去120秒已观察的幅度代理，分别建立快/主窗参考。不是同一个峰值提取器或同一个时间范围 |
| 幅度比例 + 持续时间 | 用户自定义标记按参考幅度比例及用户设置的持续时间找低流量间隙 | 借鉴组合判定与可复核数值。10%/70%并非从OSCAR用户标记默认值抄来；我们固定10秒并保留完整源秒证据 |
| 已有事件与重复标记处理 | `SearchApnea` / `SearchEvent` 可抑制用户标记与已有事件重复，按设置还可重同步 | 借鉴避免重复计数的原则。我们使用同过程互斥及配置化身份，重扫保护人工事件；不采用其重同步修改设备事件的行为 |
| 原始波形、来源、注释时间和时长分离 | S9由`LoadEVE`导入设备注释，`LoadBRP/PLD`独立导入波形与参数 | 保留原始流量，派生曲线单独命名；保存原始自动证据，人工修改边界不重算该证据。各配置/版本/批次分别保存，不能叠加当独立事件 |

OSCAR的参考是它的 **UF1/UF2用户自定义标记处理**，不是ResMed隐藏固件。我们没有复制OSCAR的GPL实现代码到检测器，没有声称复现其呼吸零交叉分段、滤波或设备分类。

以下来自本项目的独立设计：因果冻结与恢复、源秒质量/状态切断、固定10秒的源秒支持、长过程参考沿用、完整减弱过程证据、版本化扫描与人工反馈隔离。旧v3的25%/50%、去背景、形态回溯等规则保留为旧版本对照，未直接当作新方案的暂停/低通气定义。

## 比例和持续时间的来源边界

[AASM公开评分说明](https://isr.aasm.org/helpv5/ScoringRespiratoryEventsR.html)与[AASM任务组原始论文](https://pmc.ncbi.nlm.nih.gov/articles/PMC3459210/)讨论了成人暂停的大幅幅度下降、至少10秒，以及低通气的至少30%下降、10秒与血氧/觉醒支持；同时满足暂停与低通气时按暂停处理。本实现只参考其中的幅度、时长和类别优先原则，使用的是独立幅度代理，不等同完成这些评分条件。

OSCAR源码固定到 `v2.1.1 / 4f14624616d62c6986788417bc5c519c807a7ade`：

- [calcs.cpp](https://gitlab.com/CrimsonNape/oscar-sql/-/blob/v2.1.1/oscar/SleepLib/calcs.cpp)：`SearchEvent`、`SearchApnea`、`calcPeaks`、`flagUserEvents`、`flagEvents`。
- [resmed_loader.cpp](https://gitlab.com/CrimsonNape/oscar-sql/-/blob/v2.1.1/oscar/SleepLib/loader_plugins/resmed_loader.cpp)：`LoadEVE`、`LoadBRP`、`LoadPLD`。

此前REA静态检查、S9注释与截图核对、原v3审查记录保留在 [OSCAR / REA研究报告](research/OSCAR_REA_ANALYSIS.md)。该报告中关于YA70“机器总流量”的判断已被本次用户更正取代；当时的数值回放仍仅代表对应旧算法和参数。

## 接口与回归

新方案沿用 `/api/analyze`（只读）、`/api/detect`（显式扫描保存候选）、`/api/wave`、扫描批次与反馈导出。MCP源码已支持该profile，运行旧服务或旧MCP连接需要重启才能加载；不能把旧连接未成功的调用算作已执行。

```python
profile = "patient_flow_v4"
dynamic_method = "absolute_mean"
window_seconds = 5
min_duration = 10
```

派生曲线前缀为`患者流量v4{W}秒`，后缀为`强度 / 参考 / 10%门限 / 70%门限 / 剩余比例 / 1秒强度 / 1秒参考`。`剩余比例`显示为百分数，其余为L/min；不复用旧v3的去背景曲线或参数。元数据字段为 `patient_flow_v4_version`。

事件、缓存、批次身份包含profile/版本/窗口/方法/最短持续，人工反馈只包含所选配置。自动快照记录本次输入语义；人工改动不覆盖原始数值证据。仍需通过完整人工复核连续区间后，才可报告精确率/召回率改善；候选数量的升降本身不构成准确率证据。
