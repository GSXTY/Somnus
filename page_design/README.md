# 页面设计模块

页面 agent 负责本目录的总览界面、导航、空态、错误态、响应式布局和前端构建；主 agent 负责需求拆分、分派和验收。实际开发职责见 [架构与分工](../docs/AGENT_PLATFORM_PLAN.md)。

## 当前工作台

- `frontend/`：React + Ant Design 工作台源码与测试。
- `web/`：`npm run build` 生成的生产页面与本地资源，由统一 Python 服务提供。
- `dashboard.html/css/js`：保留的旧版统计页面，不是当前 React 工作台入口。
- `events.css` 与 `vendor/`：检测工作区的企业风壳层、蓝白控件与本地基础资源；宽屏184px侧栏/72px白顶栏与主工作台一致。
- 首页“数据丢失率”环图读取独立 `data_quality` 计数；未知或应上报量为0显示—，不由告警或在线率推算。

在项目根目录运行 `python launcher.py`，访问服务输出的本机首页。侧栏“数据分析”进入App内 `/#analysis`，首页快捷卡保持移除；检测页默认动态基线 v3（去背景绝对值法、8秒窗口、最短持续10秒），患者流量 v4 暂停与低通气候选方案可手动选择。主应用固定顶栏与主导航，仅中间内容滚动。数据分析首次进入后保留同源 `/events?embedded=1` 框架，切换模块不卸载，因此CSV、波形位置和复核浏览状态保留；旧 `/events` 仍支持独立兼容访问。

工作台合成演示用户不会自动绑定本地 CSV；进入检测后需选择或导入实际记录。当前记录候选与演示统计不混合。

## 开发与验证

```powershell
cd page_design/frontend
pnpm test
pnpm build
```

开发服务器的代理仅用于本地前端开发，集成验收使用 `launcher.py` 提供的同源地址。检测算法、标记、批次和导出由 `event_detection/` 对应 agent 维护；纯导航衔接修改先协调文件所有权。

生产构建后，可在项目根目录运行只读集成检查（替换为统一启动入口实际输出的地址）：

```powershell
node tests/workbench_navigation_smoke.cjs http://127.0.0.1:8765/
```

该检查读取生产资源、事件页及返回入口，不导入记录、不触发扫描、不写入标记。浏览器中的实际点击往返另由主 agent 验收。

## AI 数据助手

左侧独立入口 `/#assistant` 提供会话历史、新建/重命名、历史恢复和流式对话。模型经同源后端调用，页面不收集密钥。配置状态、失败和中断均明确显示；未配置时可管理会话但不能发送。数据库未连接，不执行数据查询或展示虚构查询图表。具体接口与前端模拟测试说明见 `frontend/README.md`，模型服务由对应功能agent维护。

## 深度分析试用

左侧“深度分析”或 `/#deep-analysis` 是独立于普通聊天模型的分析入口，兼容经典/暖陶玻璃两种外壳。用户可下载后端合成日报样例、选择CSV并提出问题，查看独立模型配置、Docker和执行镜像状态，创建/取消任务以及读取图表、报告与执行记录。仅展示代码和执行输出，不展示模型内部思考。原数据分析iframe仍为同实例保活，不因进入此页重新加载。

这是 DeepAnalyze 协议兼容试用，不表示已安装或运行 DeepAnalyze-8B。模型或执行环境未就绪时，“创建试用任务（检查条件）”只记录后端阻塞状态，不调用聊天模型、不生成假计算结果。需要服务器独立配置 `DEEP_ANALYSIS_BASE_URL / DEEP_ANALYSIS_MODEL / DEEP_ANALYSIS_API_KEY` 和Docker执行镜像；页面不录入密钥。详细执行条件见 `deep_analysis/README.md`。
