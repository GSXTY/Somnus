# Native history, continuation and forks

Native history is authorized by a visible Somnus conversation and root task. Only the desktop host can bind the real DSH session, immutable task owner and observed sequence range. Child session records contain only verified parent links and ranges; they grant no independent file or tool rights. Raw events are paged from the native host after this ownership check, not copied into the task state ledger or inferred from message adjacency.

Host binding: `POST /api/assistant/conversations/{cid}/native-sessions` with turn_id, owner_id, session_id, start_seq, last_seq, optional assistant_event_seq and children (session_id, parent_session_id, source_seq, last_seq). Owner finish accepts the same native_history document. Final history, assistant result and canonical terminal status commit in one SQLite transaction. The existing encrypted result outbox retries persistence only. It never invokes the model again. Valid terminal receipt replays can repair metadata without overwriting results or restoring old authorization.

Fork: reserve with turn_id and at_seq (optional registered child_session_id), run the actual native session/fork, then commit its returned session identity and source checkpoint. Reserve creates no visible conversation. Commit creates a new read-only conversation and its native identity atomically. It copies no active tool authorization, pending proposals or approval decisions. Retries are idempotent and cannot swap the child identity. Failure aborts only an uncommitted reservation. Child forks use staged, paginated inherited-history archives (plain user/assistant text with real seq/part provenance); parent conversation summaries are never presented as child history. Legacy bounded display_history remains an older-client path. See NATIVE_FORK_PAGINATION.md for atomic upload, limits and restart verification.

Ordinary project forks retain and recheck the same project roots. Default local forks inherit a strict local_origin_cid, so the host derives only its controlled home/somnus-conversations/{origin} directory; callers cannot provide arbitrary paths. Git worktree forks require explicit share-current confirmation. A verified shared reference retains the same canonical worktree owner and directory identity; no Git branch or file mutation is performed. New conversations default to read-only and receive no old approvals. Binding changes invalidate shared references rather than falling back to the base repository. Old messages with no verified native history keep the existing message-only branch option; they must not be labelled native forks.

Interrupted tasks remain interrupted. Explicit Continue submits a new authorized turn against the bound native session; Retry is a separate explicit request. Neither resumes old tool calls or approval grants automatically. Observed child sessions remain read-only/stop until an explicit real fork creates an independent conversation. The child conversation pane then supports fresh authorized turns with its own model, up to three Skills, attachments and permission checks. These per-conversation model/Skill preferences persist with revisions; source routing is only an initial fallback.

Declarative plugin cards preserve existing MCP text and accept bounded text, lists, metrics, tables, bar/line charts, status blocks and typed forms. Actions include insertDraft, open-own-page, read-own-settings and save-own-settings; settings writes are restricted to the same plugin declared section, schema and revision. They execute no HTML, script or arbitrary commands. Existing list50/metrics16 limits remain legal; text uses UTF16 code units and document bytes use compact UTF8 JSON. Shared Python/Node/frontend fixtures verify matching acceptance rules, not arbitrary third-party browser-client compatibility. Tool source identity is derived from the selected plugin's unique MCP binding, attached to the prepared tool catalog and checked against result identity by the host. Ambiguous ownership produces no card. Native owner receipts protect final card persistence, including delayed completion.


Native forks leave Somnus agent_mode unset and follow the forked runtime's actual preset. A Creator parent does not force its child into Creator mode. Workspace scope is fingerprinted from workspace identity, validated root identities and worktree bindings only: normal file edits, project names and pinned state do not rotate sessions. Changing roots invalidates the current head; a new authorized turn may bind a new native session. Late old receipts may update the old turn history but cannot reclaim the head. Permanent session ownership includes root history and observed child identities, so invalidating a head cannot make its session available to another conversation. Temporarily inaccessible declared roots fail explicitly instead of falling back to another directory.

ACP normal and group prompts consume the same Runtime Settings task policy as native tasks. Default maxDurationMinutes=0 means no total execution cap. Idle time emits a diagnostic notice and keeps waiting. A nonzero maximum is an explicit cap; process exit and protocol rejection remain real failures and never cause a sent prompt to be replayed. Startup/login/individual approval and automatic tool-delegation budgets remain independent.

The cross-platform gate includes new backend session/card tests, ACP deadline and real synthetic ACP process checks, all host runtime contract tests, and the frontend preferences/child conversation/declarative document tests. The installed-DSH acceptance is a separate local command: `node tools/native_runtime_acceptance.cjs`. It uses a temporary native profile, real session/fork, synthetic parent/child events and the loopback-only fake model fixture. No paid provider or user profile is used. Its required local installed runtime makes it unsuitable as an unconditional fresh-CI dependency.

The child pane and trajectory also expose authorized file browsing/preview/diff, watched directory refresh and a real local PTY terminal where supported by the installed host. Scope is derived from the selected conversation and invalidated on directory changes; terminal commands are actual local processes, not chat draft simulations. Local real-PTY acceptance is separate from the static gate. The current work explicitly excludes remote control; existing remote data gateways remain available.

The frozen-backend acceptance command is `python tests/verify_workspace_compat_frozen.py <backend.exe>`. It runs real HTTP against two fresh process launches with an isolated non-hidden temporary profile and Git repository, verifies a 240-record archive exceeding512KiB by SHA256 after restart, preserves dirty/untracked worktree hashes, and checks preference and expanded card persistence. Only its synthetic turn transport is promoted through the fixture database; no model or business tool is invoked. Failed profiles/logs are retained for diagnosis.
