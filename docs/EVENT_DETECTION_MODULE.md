# 事件检测模块

## 定位与当前目标

`/events` 是单份本地 CSV 的检测工作区，服务于查看波形、自动扫描、候选证据复核、人工标记、历史批次及反馈导出。它是用户数据分析中的一个功能，不承担全体用户运营统计。

检测目标始终是当前打开的 CSV。添加多个文件后，每次仅分析当前选中的记录；页面信息区显示当前记录信息。当前没有数据库用户与文件的关联，不得将文件名、任意 URL `user_id` 或总览中选中的用户视为绑定凭据，也不得据此宣称正在检测该用户的数据。

## 入口与接口边界

- `/` 的用户运营总览使用 `GET /api/dashboard`，接口字段可在统一服务的 `/docs` 中查看。
- `/events` 保留直接添加本地 CSV 的入口；导航可返回用户运营总览。
- 原本地记录统计迁至 `GET /api/recording-overview`，保留 `files`、`summary`、`current_recording` 结构，仅供记录工作区使用。CSV 覆盖时长不是设备实际使用时长，不得纳入用户使用时长指标。
- 现有检测、事件、批次与导出接口继续服务当前记录。本轮不改变算法、扫描参数、保存逻辑或反馈格式。

后续用户入口应为“用户 → 该用户记录 → 选定记录检测”。启用前，数据层必须提供真实的用户标识、记录标识及两者映射，并据此加载选定记录；页面需能明确展示加载的记录及其所属用户。仅传入 URL 参数不能完成绑定。映射尚未接入时，总览用户记录入口应展示“记录待接入”，不提供伪造关联的检测跳转。

## 复核与数据含义

自动扫描结果是待人工复核的工程候选，保留确认、修改、忽略和补充漏标流程。历史跨批次、方法或窗口的候选可能重叠，不能相加作为独立临床事件数。检测不输出临床 AHI，也不据此调整设备。

原始自动快照、人工变更历史及反馈导出继续沿用既有实现；本轮标题与目标提示调整不改变这些行为。

## 协作边界

检测模块维护其工作区及检测功能。用户运营总览页面由页面模块维护，用户数据层、HTTP 路由及接口整合由主 agent 协调；涉及跨页面入口或用户与记录关联时，先明确数据映射及接口约定，再实施接入。
