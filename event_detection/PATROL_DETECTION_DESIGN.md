# 内部数据巡检与异常排查：检测模块设计

**建议方案，待用户确认，未实施。** 本文只提出架构、功能和验收建议，不代表已接入用户数据库或已实现跨用户统计。所有新增阈值、匹配规则、批次选择和计时策略均须由用户确认后再实施；文中示例不是检测参数的修改指令。

## 1. 目标与首版边界

把已有单记录检测与人工复核接入“按日发现 → 按用户/记录定位 → 波形复核 → 留存结论与证据”的内部排查闭环。巡检结果用于安排人工检查，不作临床判定。

首版建议只汇总已经由使用者主动完成的扫描，不自动批量扫描，不自动确认或忽略事件，不自动修改算法参数，不计算临床 AHI。没有扫描、归属或时钟证据时展示未知及原因，不能显示为零异常。巡检发现条件、排序权重、异常阈值和比较基准均待确认，首版可以先提供按状态与覆盖情况筛选。

## 2. 已有基础与缺口（只读核对结果）

| 结构 | 已有能力 | 巡检仍缺的能力 |
| --- | --- | --- |
| `event_store.py` | 以 `file_id` 保存事件及 revision；以 `run_id` 保存自动快照；快照含设置、范围、原始候选；另有批次索引和归档 | 真实用户与记录映射、巡检统计快照、代表批次决策记录、统一覆盖模型 |
| `EventStore.write` | 版本冲突检查；保存整份 before/after、操作时间、reviewer、应用版本；自动快照与事件提交在同一事务 | 强制可识别的复核身份、原因、逐事件操作类型，以及人工拆分/合并/替代关系 |
| `viewer.py` 的 `/api/detect` | 核对当前文件、串行扫描、保存成功结果；快照含 `event_links`、warnings、`analyzed_rows`、`eligible_seconds`；扫描失败不产生本次成功快照 | 持久化任务失败/取消状态、请求与实际覆盖区分、跨记录调度与巡检查询 |
| `detector.py` 与具体算法 | 按方案调度，设置及部分事件证据包含算法版本、输入、方法、窗口等；各方案保存独立候选 | 各版本统一的完整配置标识、按类型的有效分析区间及排除原因、统一可比性声明 |
| `feedback_export.py` | 按范围/类型导出；区分逐条与完整检查；待复核、缺失结论或估算轴标记可阻止完整声明；跨边界标记单列；反馈包有内容哈希与清单 | 巡检统计的复现清单、用户归属版本、代表批次选择及完整审计链导出 |
| 本地页面 | 当前记录波形、候选跳转、确认/忽略/修改、人工新增、历史批次和反馈 | 按日巡检入口及经过验证的“用户 → 记录”入口 |

当前自动结果去重存在“相同 ID”以及部分旧方案的同类型、同时间轴、同输入且重叠比例达到既有条件的匹配；动态基线等方案主要按精确 ID 保留独立结果。此机制用于保存时复用事件，不是跨用户、跨文件或跨日统一去重规则，不建议直接复用为巡检计数规则。现有批次指纹也不能直接认定已涵盖未来所需的全部输入、预处理和计时配置。

本次仅阅读结构，没有运行开发测试，也没有验证所有历史记录的字段完整性。

## 3. 建议的巡检闭环

1. **按日发现。** 选择上海自然日和算法配置组，显示记录待归属、待扫描、部分扫描、质量不足、待复核及已完成复核等状态。事件发生日与扫描完成日、复核操作日分开筛选，默认建议按发生日展示，但需用户确认。
2. **定位用户与记录。** 每条汇总可展开贡献记录、归属来源、代表批次、覆盖及排除原因。未绑定记录进入“待归属”队列，不进入任何用户的事件指标；演示记录单独标记并隔离。
3. **进入波形。** 通过经验证的记录标识加载对应内容指纹，展示用户归属、批次设置、时间轴与复核状态。加载后核对内容；不匹配时停止定位，不悄悄使用当前打开的另一份 CSV。定位应保留事件前后上下文，具体时长待确认。
4. **人工复核。** 人工确认、忽略、修订或补充事件，记录原因及检查范围。仅处理列表中的候选不等于完整检查整个记录。
5. **回看结论。** 日汇总以选定代表批次和固定复核 revision 生成统计版本；人工变更后生成新版本，保留旧版本及变化来源，避免同一报告无痕变化。

## 4. 真实归属与记录身份

建议数据层分别维护稳定的用户标识、逻辑记录标识和文件内容指纹。指纹证明内容相同，不能证明用户归属；文件名、URL `user_id`、浏览器当前用户都不是归属证据。

归属需来自受认可的业务映射或经授权的人工核验，记录来源、核验人、核验时间、有效范围和版本。一个记录在同一有效范围应有唯一明确归属；冲突、换机、共享设备或缺失归属进入待处理队列。设备属于某用户不能自动推导设备所有历史文件都属于该用户。归属修正后重建受影响汇总，保留旧报告引用的归属版本。

同一逻辑记录或同一已验证用户内的同一内容重复导入，建议只形成一个统计贡献；内容相同却归属于不同用户时应进入归属冲突处理，不能仅靠指纹跨用户自动合并。不同文件内容可能包含同一段采样，需另有来源记录/片段关系。尚不能确认跨文件重复时显示“可能重叠”，不简单累加用户日总数或宣称已去重。首版可隔离冲突记录，分别供复核，具体处理策略待确认。

## 5. 扫描覆盖、有效分析与人工检查分别建模

建议使用左闭右开区间 `[start,end)`，但最终边界定义须确认，并兼容现有各算法的实际计时语义。

| 概念 | 建议含义 |
| --- | --- |
| 记录目标范围 | 此记录被指定需要检查的范围及事件类型；缩小目标不能改称“整份文件已完成” |
| 请求扫描范围 | 使用者请求扫描的区间及类型，不代表所有秒均可分析 |
| 实际完成覆盖 | 成功完成计算的输出区间及类型；基线前置上下文不计为已扫描输出 |
| 有效分析区间 | 在该算法、类型、配置下满足数据质量、所需通道、状态及参考条件的区间 |
| 人工检查覆盖 | 复核人声明实际检查的区间、类型和逐条/完整方式，与自动覆盖独立 |

建议状态至少区分：未扫描、执行中、失败/取消、已完成但部分范围或类型、整份目标扫描完成。另显示有效分析不足与复核完成度，避免一个“完成”掩盖质量或人工检查缺口。

完整扫描须具备可验证的记录边界、目标类型、成功完成状态和完整输出覆盖。扫描整份文件成功但有缺失/参考不足时，可以称“整份扫描完成，有效分析不足”，不能称“全时段可判定”。部分扫描即使没有候选，也只能说明该部分输出，不能代表整份零事件；多个部分批次的区间并集不能冒充一个完整批次，首版不拼接为正式代表结果。

有效分析时长建议按该类型有效区间的并集计算，并裁剪到选定日/记录范围；不能使用 CSV 首尾跨度、样本数除以假定频率或实际设备使用时长替代。缺失、无效样本、参考不足、状态变化及算法特定排除项需保留原因，重叠原因不重复扣时。当前不同方案 `eligible_seconds` 的计算条件不同，且单个总数不足以按日裁剪，不能直接升级为统一分母。无法提供区间时，有效时长和相关率指标应为未知。首版建议不提供按时长归一化事件率，待时钟与分母验收后再议。

## 6. 算法配置组与代表批次

建议配置组键包含：方案、算法版本/构建标识、输入来源及通道角色/单位、预处理版本、方法、窗口、持续条件与比较符、比例/幅度门限、事件类型集合、时间轴及边界规则、参考/质量/干扰策略。完整规范化配置及其哈希保留在证据中；应用版本单独保存。字段缺失的旧结果进入“历史配置不完整”组，不猜测默认值后混入新组。

**建议每个逻辑记录、配置组、目标范围版本只选择一个已成功完成的代表批次。** 先满足完整目标覆盖和元数据可验证条件，再从合格批次中建议默认选最新完成者；也可由人员指定并记录原因。该默认规则与“最新”的时间来源、同时间排序规则均待确认。批次有效分析不足仍保留质量限制，不因成为代表而变成完整可判定。

没有合格完整批次时，正式记录/用户日完整指标显示未知或“仅部分结果”；可单独展示一个选定部分批次的局部结果，明确范围和类型，不将多个批次相加。全零但完整的批次是有效代表，不能回退到更早的非零批次。扫描失败或正在执行不能替代代表批次。归档只控制历史展示，不应静默切换统计来源；代表被撤销/失效时显式重选并生成新统计版本。

同一记录同配置重复扫描，只统计代表快照及其关联复核结果，其他批次用于对照。不同配置组并排比较，不相加。记录跨多日时建议沿用一个代表全记录批次再按日分配，避免逐日独立选批造成边界或人工结论不一致。以上为建议，不新增任何自动批次选择行为。

## 7. 候选、确认、忽略及人工补充的统计

建议保留两组平行视图：

- **原始检测产出：** 代表批次快照的原始候选总数，固定不随人工操作变化；逐条通过原始 ID 和 `event_links` 映射到选定 revision 的待复核、已确认、已忽略或关联未解决状态。关联未解决不能算忽略；状态分项加未解决应能核对原始总数。
- **当前复核结论：** 在明确人工检查范围内的当前事件，分别统计待复核、已确认、已忽略；按“来自自动候选”与“人工新增”分开。人工新增不增加原始自动产出。忽略表示拒绝该候选，不表示整段信号正常；人工确认表示工程复核结论，不是临床确诊。

人工边界/类型改变时，原始视图按原快照归类，当前结论按修订后归类，明确两者可能跨类型或跨日迁移；不能将两个视图相加。若多个原始候选最终关联同一人工结论，原始产出仍可按候选审计，当前结论只按结论身份计一次，并显示多对一关系。拆分、合并及跨文件身份匹配需要显式关系或人工裁定，不按时间重叠自动认定。具体匹配阈值不在本轮确定。

## 8. 跨午夜与时间可信度

建议事件发生日采用经过核验的绝对时间，转换为 Asia/Shanghai 自然日。**数量建议按事件起点归属一天，持续时间按与各自然日的交集拆分。** 例如 23:59:55 至次日 00:00:10，首日计一个事件、5 秒，次日计零个新起事件、10 秒；次日另显示“跨日延续 1 条”，不能混入新起数量。结束恰在午夜的事件不向次日贡献持续时间。

数量与持续时间分别按候选/确认/忽略展示。多事件重叠时建议明确提供“逐事件持续时间之和”与“覆盖时间并集”两种不同概念，首版优先展示并集并保留事件明细；不同类型或状态的并集不能再次相加称总覆盖。边界事件缺少前后完整上下文时单列，不能把裁剪后的段落当成新完整事件。

以上数量、切日与边界策略均待确认。跨文件可能是同一事件而缺少连续性证据时，不合并推断；在用户日合计前要求处理重复/连续性冲突，否则仅展示记录级结果与限制。

源时间戳只有秒级、重复时间戳的秒内顺序来自估算、时区不明或设备时钟跳变时，需分别记录“绝对日期可信度”和“采样间隔可信度”。不能只因能解析时间文本就认为采样时钟已验证。无可信日历映射的记录不进入按日事件指标，留在未定位日期队列；能核验日历而不能核验采样间隔的记录可按明确标签展示工程候选，但不与可信采样记录混做持续时间、事件率或窗口敏感性排名。

秒内重建与原始秒级时间轴不能无损互换。比较必须同配置、同输入及单位、同时间语义、相近质量与覆盖条件；不满足时显示不可直接比较及具体原因。有效分析时长是算法条件下的工程分母，不是设备使用时长，更不是睡眠时长。

## 9. 修改、新增与原快照追溯

现有不可变快照、`event_links` 和 revision before/after 是基础，但未来巡检建议补充显式谱系：原始 `run_id + original_event_id` → 当前结论 ID → 修订号，操作人、时间、操作类型、理由、前后边界/类型/状态及配置归属。保留原始证据，不以人工边界改写算法原始证据。

人工新增标记须写明来源为人工、依据记录与检查范围、操作者、理由和创建时间；没有原候选就明确原候选引用为空，不伪造算法命中。拆分/合并保存所有父子关系；删除或无法关联保留审计状态，不能消失为零。人工内容未经配置归属裁定，不自动归入每一个算法版本的结果。

巡检报告固定使用代表批次、归属版本、复核 revision、配置组与计时规则版本。后续修改生成新报告，可追溯差异；旧报告重开应复现旧状态。现有 reviewer 字符串和 before/after 不等于已经具备完整的身份认证与逐事件谱系。

## 11. 建议证据包

建议沿用现有反馈文件夹的原 CSV、完整自动 JSON、范围化复核 JSON 和哈希清单，并在未来增加巡检报告清单：日期/时区、真实归属证据引用及版本、记录指纹、配置与计时版本、代表批次选择理由、扫描与有效覆盖区间、排除原因、复核 revision 和原候选/当前结论映射。缺失内容标为缺失，不补造。

每个排查项附原始与修订边界、上下文波形所需的通道/单位/样本定位、强度/基线/门限等已有证据、压力/总漏气与质量提示；图像只是辅助，不替代原样本。保存的证据字段按实际算法能力提供，不宣称所有旧方案均具备相同证据。谱系补充记录与现有精简复核 JSON 分离，不擅自更改既有导出格式或把整份审计反复嵌入每条反馈。

内部巡检默认只读定位；导出原始数据仍由人员主动发起，遵循既有确认流程，不自动上传。

## 12. 待实施后的验收场景

| 场景 | 建议预期 |
| --- | --- |
| URL 指定用户但文件未绑定/归属冲突 | 不计入该用户、不显示绑定成功，进入待归属 |
| 同 CSV 重复导入；不同文件疑似同源重叠 | 前者只贡献一次；后者显示冲突并阻止无条件累计 |
| 仅扫描 10 分钟且零候选 | 显示部分扫描，整份结果未知，不能称整日正常 |
| 整份扫描完成但大量缺失或参考不足 | 显示扫描完成与有效不足两个事实；无区间证据则不报有效时长 |
| 连续两次同配置完整扫描，最新为零；另有失败批次 | 只选合格代表，零结果保留；失败不替换；旧候选不混入 |
| 窗口、类型集合、输入或版本不同 | 分组对照，不累计；历史缺字段独立标示 |
| 跨午夜、结束恰午夜、重叠事件 | 起点计数与跨日延续分开，时长拆分可核对，覆盖并集不重复 |
| 估算秒内时间或未知时区 | 限制比较/按日归属；不生成虚假的精确率指标 |
| 候选确认、忽略、修改类型、跨日改边界、人工新增 | 原始产出不变，当前状态/归类随 revision 更新；新增独立可追溯 |
| 多对一关联、拆分/合并、关联丢失 | 有显式谱系并能核对总数；未解决不当作忽略 |
| 只逐条复核；选定范围有待复核或边界事件 | 不自动宣布整份完整检查；未知区域保留未知 |
| 归档代表批次或修正用户归属 | 不静默换来源；新报告记录变化，旧报告可复现 |
| 波形加载期间切换文件或并发复核 | 核对内容身份与 revision，避免误写和旧结果覆盖 |

这些是未来验收建议，本轮未新增或执行测试。

## 13. 请用户确定后再实施的事项

优先确认：真实归属的认可来源与冲突处理；首版按发生日还是操作日发现；目标类型/覆盖定义；完整代表批次的选择与人工指定权限；起点计数、跨日拆分及重叠时长展示；采样时钟验证条件与不可比记录展示；人工谱系及复核身份要求。异常阈值、匹配门限、定位上下文时长和任何新增计时规则另行确认，本文不设置默认检测门限。

建议先验收“记录身份与覆盖可追溯 → 单记录代表批次及复核对账 → 按日用户定位”，再讨论自动化扫描或跨记录比较。此顺序仍为建议，未经用户确认不开始实现。
