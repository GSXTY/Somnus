# 内部数据巡检与异常排查：页面设计建议

> **建议方案，待用户确认，未实施。**
>
> 本文仅提出页面结构、交互与验收建议，不代表已上线功能、已连接数据库、已运行扫描或已接入分析助手。所有阈值、异常判定、优先级和自动生成规则均待用户确认；第一版建议先展示描述性变化，不直接给出“异常”结论。本轮只新增本文，不修改代码、页面、测试或数据库，不运行开发测试。

## 1. 目标与信息顺序

面向内部数据巡检人员，以“发现 → 定位 → 复核”为主流程：先理解数据来源与覆盖，再查看候选变化及待排查事项，定位到可验证的记录与波形，最后记录人工复核结果。首页回答“哪些数据已具备分析条件、哪里发生了可观察的变化、有哪些证据需要查看”，不输出临床诊断、临床事件率或 AHI。

注册增长、活跃用户和日均实际使用时间保留在次级“运营概况”视图，统计使用实际使用区间及活跃用户日口径。运营使用时长与检测有效分析时长属于不同概念，不共用分母。

当前数据库、记录归属和批量巡检能力均不能假定已经接入。本地单份检测仍可通过既有 `/events` 打开；没有用户映射时，巡检只能在已知记录范围内展示结果，不能形成用户榜单。

## 2. 导航结构建议

```text
数据分析工作台
├─ 巡检总览（建议未来首页；本轮不改路由）
│  ├─ 覆盖与候选总览
│  ├─ 每日趋势
│  └─ 待排查事项 → 事项详情 → 记录 → 波形复核
├─ 数据记录
│  └─ 记录详情 → 扫描批次 / 通道质量 / 波形复核
├─ 用户查询（仅在真实归属映射接入后可用）
│  └─ 用户详情 → 有权限且已验证归属的记录列表
├─ 运营概况（次级）
│  └─ 注册增长 / 活跃用户 / 日均实际使用时间
└─ 单份本地检测（沿用 /events，不隐含用户关联）
```

“分析助手”建议作为随上下文打开的侧栏入口，不另设一个能绕开筛选和数据权限的通用对话首页。页面设计独立聊天继续对应 `page_design/`，与产品运行时的助手能力分开说明。

线框中的覆盖分母、批次选择、时长合并及事项生成均为待确认的数据能力，不由前端猜测。首屏不用一个没有覆盖说明的候选“大数字”表示整体风险，不以红色健康告警包装描述性变化。

## 4. 覆盖、计数与趋势的展示口径

### 4.1 数据覆盖先于变化解释

建议覆盖区域并列显示以下项目，来源不足时逐项显示“— + 原因”：

| 展示项 | 建议口径与可见限制 |
| --- | --- |
| 纳入记录数 | 当前权限和筛选内的去重记录数；标明清单是否完整。应有记录总数未知时仅展示已知纳入数，不生成覆盖百分比。 |
| 扫描覆盖 | 已完成所选方案扫描的记录数 / 纳入记录数。部分扫描要另列，不能整份记为已完整扫描。 |
| 有效分析小时 | 所选方案、批次和范围内，具备有效输入且实际纳入分析的时间区间汇总；附无效、缺失、参考积累等排除说明。需由检测服务提供可追溯区间，不能用 CSV 首尾跨度代替。 |
| 可评估小时 / 时间覆盖 | 可评估区间的定义、数据完整性和分母来源须先确认。尚无可靠分母时显示“时间覆盖未确定”，不把扫描覆盖比例当作时间覆盖。 |
| 排除与未知 | 展示未扫描记录、部分扫描范围、缺失通道、时间质量问题、无效输入及未知时长。排除原因可能重叠时提示不可直接相加。 |
| 涉及用户 | 仅对已验证用户归属的记录去重；混有未关联记录时分开展示“已关联用户数 / 未关联记录数”，不宣称全体涉及用户数已知。 |

重复导入的同一内容、重叠扫描和历史方案结果不能重复累加。建议由主协调与检测模块先确定有效区间合并策略和唯一结果选择规则；页面展示实际采用的版本与规则。跨记录若无法识别同一暴露来源，不能声称已消除重复暴露；此时不提供跨记录统一密度，或仅分记录展示并注明限制，具体策略待确认。

### 4.2 候选数量与密度一起显示

候选密度建议名称为“每有效分析小时候选数”，计算为同一范围、方案、批次选择下的候选原始数量 ÷ 有效分析小时。它是工程筛查描述量，不是独立临床事件数或临床发生率。

- 必须同时显示原始候选数量、分母时长、选定范围和批次。分母为未知或 0 时密度显示“—”，不能显示 0 或无穷大。
- 只有扫描完成、有效分析时长已知且大于 0、结果确实为空时，才能显示“0 条候选 / 0 候选每有效分析小时”；仍不能推断“正常”。
- 范围边缘候选如何计数、跨午夜如何归日、跨批次候选如何去重，均需确认统一服务口径。建议前端只展示服务返回的计数，详情给出入选依据，不在页面自行重算或假定按起点归日。
- 原始数量指按已声明批次选择及去重规则得到的候选条数，未做时长标准化；不代表把所有历史扫描原始行数相加。候选被忽略后，保留原始检测量，另列复核状态，不能悄悄重写历史检测数量。

### 4.3 每日趋势与对照期

建议默认显示最近 7 天，对照为紧邻的等长前一期；这是交互建议，待用户确认。支持近 30 天和自定义范围，日期按上海自然日含首含尾。自定义对照必须显式展示两段起止日，长度不同时提示不能直接比较原始总量。

趋势区建议用两个相邻图表：左图可切换原始候选数与候选密度，右图显示有效分析小时及已知覆盖。每个悬停点同时提供日期、原始量、有效小时、密度、覆盖及可比性。提供每日数据表，便于键盘与移动端查看。

缺失、未扫描、未知分母用空隙和状态文字；已分析且确实为零的日期画零点。对照期算法、参数、输入通道或有效分析区间定义不一致时仍可分开展示事实值，但不连成具有同口径含义的对比线，不输出增减百分比与“上升异常”结论。对照值为 0 时不用百分比除零，展示“本期 X，上期 0”。

覆盖不足的阈值尚未确定，第一版只展示可确认的缺口与数值；标识可写“覆盖限制，变化需复核”。如未来采用最少有效小时、最低覆盖比例或密度变化阈值，须先确认规则与版本。

## 5. 待排查事项与详情

事项是“需要进一步核实的观察或数据缺口”，与波形候选、人工复核结果分别建模。第一版可展示人工整理或服务明确返回的描述性事项；不能由前端臆造阈值或自动判定异常。

每一条事项均须保留以下字段；窄屏卡片可折叠次级字段，但不能省去它们：

| 必需字段 | 列表摘要 / 详情要求 |
| --- | --- |
| 事件类型 | 使用检测方案的候选类型原名，加“候选”限定；数据覆盖事项写“数据质量 / 覆盖”，事件类型填“不适用”，不伪装为检测结果。 |
| 范围 | 起止日期、时区、记录集合或记录标识、分析区间、筛选条件；记录级还是已验证用户级必须明确。 |
| 对照期 | 明确起止日及同口径要求；没有对照就写“未设置 / 不可取得”，不能默认为零。 |
| 原始数量 | 本期与对照期分别展示候选数量，并给出批次选择与重复处理说明；未知为“—”。 |
| 每有效分析小时候选数 | 本期与对照期分别展示，附分母；未知或零分母显示“— + 原因”，不把名称简写成临床事件率。 |
| 暴露时长 / 覆盖 | 有效分析小时、可评估小时及覆盖比例（若已知）、完成/部分/未扫描记录数、数据质量限制；没有可靠定义时写“待接入”，不换用文件跨度。 |
| 涉及用户 | 已验证的去重人数及未关联记录情况；当前仅记录级时写“用户归属未接入，涉及 N 份已知记录”，不得显示用户排行或假用户。 |
| 算法 / 参数可比性 | 算法名、版本、参数摘要、输入/通道、时间模式、批次、覆盖定义；明确“可比 / 不可比 / 未知”及原因，不能只靠方案名称判断。 |
| 证据 | 记录标识/内容指纹、扫描批次、候选标识、起止位置、质量说明和检测快照；摘要可展开或进入详情查看，不用助手文本替代原始证据。 |
| 下一步 | 根据缺口提供“查看记录 / 查看覆盖 / 进入波形复核 / 选择可比结果”等入口；条件不足的按钮禁用并说明缺少什么。 |
| 工作状态 | 建议“待定位 / 待复核 / 已复核 / 暂无法判断”，状态含义与保存方式待确认；与单条候选的确认/忽略状态分开展示。 |

示例事项（仅为字段示意，不是实际结果）：

```text
观察：所选记录的“减弱候选”数量存在变化，原因待复核
范围：记录 R-示例，当前期 D1–D7；对照期 D-6–D0（均为上海日期）
当前期：原始候选 —；有效分析小时 —；候选/有效小时 —；覆盖 —
对照期：原始候选 —；有效分析小时 —；候选/有效小时 —；覆盖 —
涉及用户：归属未接入，仅记录级分析
可比性：待核对算法版本、参数、输入和覆盖定义
证据：记录、批次与区间待取得；没有证据时不启用波形跳转
下一步：查看记录覆盖 → 选择同口径批次 → 查看候选波形 → 人工复核
```

详情页建议左侧解释观察、对照及限制，右侧列记录和候选证据。不能用不明权重给用户排序；如需排序，第一版建议提供日期、已知原始数量、已知密度、复核状态等明确字段，由用户选择。未知值单独置后并保留提示，不参与数值排序推断。

## 6. 下钻、波形复核与返回

1. 在首页应用范围、对照期、类型、方案及状态筛选；请求期间保留明确加载标识，快速切换时丢弃旧响应。
2. 点击事项进入详情，携带本期、对照期、事项标识及列表位置。用户归属未接入时只展示记录清单，不开放用户维度入口。
3. 归属接入后，用户下钻需先验证用户标识、记录归属和读取权限，再列实际记录；不能依据 URL 参数构造或暗示归属。
4. 选择记录和批次，展示内容指纹、算法版本、参数、时间模式及证据区间。只有存在真实记录映射、可读取内容和可定位区间时，才启用“进入波形复核”。
5. 进入波形页时携带记录、批次与候选标识，重新校验上下文后定位到区间；不能复用另一份记录的候选或旧波形。未来上下文协议由主协调与检测模块确定，本设计不假定该跳转已实现。
6. 波形复核沿用既有人工确认、修改、忽略等能力。保存结果前后保留检测快照；“已复核”不等同临床确诊。巡检页读取新的复核状态，不自动改变原始扫描计数。
7. “返回巡检”及浏览器后退恢复范围、对照期、来源、所有筛选、排序、分页/列表位置和展开事项。状态建议按来源与权限范围隔离，只保存必要标识；不把原始波形或身份信息塞进地址栏。
8. 返回后刷新相关事项的复核状态及更新时间。如果记录已不可读取、权限变化或快照失效，保留用户筛选并明确显示原因，不悄悄换成其他记录。

移动端建议：主导航收为顶部菜单，筛选置于可展开区；指标两列，趋势纵向；事项用卡片，详情在当前页面展开，波形复核保持独立工作区。所有图表配数据表，状态同时用文字说明，不能仅靠颜色区分。

## 7. 受限分析助手入口

建议预置问题：“当前范围哪些记录尚未扫描？”、“这两期候选变化是否具备可比性？”、“这条事项有哪些证据和覆盖限制？”、“下一步可以查看哪段波形？”。问题范围限于用户可访问、已选定的数据与确定服务能力。

侧栏顶部固定显示当前来源、日期范围、记录/已验证用户范围、方案与结果快照。回答应分列观察事实、证据、限制与可操作下一步；引用真实记录、批次和候选区间，缺少数据时明确不能判断。

助手不得猜测用户归属、把候选解释为临床诊断、以文件跨度补有效分析时长、执行任意 SQL、默默运行扫描或自动确认候选。未来若支持发起扫描，建议先呈现具体记录、区间、方案与参数供用户明确触发，且与只读提问区分。

当前模型运行时未接入时入口标注“分析助手待接入”，可展示支持问题示例，但不伪装为可用聊天、不返回预写的“分析完成”。助手连接失败不影响记录和波形工具入口。

## 8. 页面状态矩阵

来源、覆盖、扫描、结果和复核状态是独立维度，允许并存；例如“演示 + 部分扫描 + 待复核”。

| 状态 | 展示与允许动作 |
| --- | --- |
| 加载中 | 说明正在加载的范围和来源；旧数据若保留必须标注所属范围，建议新范围暂显示占位；旧响应不能覆盖新结果。 |
| 空态 | 仅在查询成功且集合明确为空时写“此范围暂无纳入记录 / 待排查事项”；保留筛选和来源说明。无事项不等于全部正常。 |
| 未接数据库 | 顶部“未连接数据库”，总体指标与用户数为“—”；可打开本地单份检测或显式演示。已有本地记录只归本地范围，不能填进总体用户指标。 |
| 未扫描 | 显示已知记录数、扫描范围“尚未扫描”；候选量、密度及复核量未知为“—”，不显示零。若批量能力未接入，扫描入口不可用并说明可使用单份检测工具。 |
| 覆盖不足 / 受限 | 展示已知有效小时、缺失与排除范围；阈值未定时仅标“覆盖限制”。不可据此输出候选增多的异常判断。 |
| 待复核 | 显示候选证据和待复核数量；带原始结果快照，允许进入真实记录复核。数量未知仍为“—”。 |
| 已复核 | 展示复核状态和更新时间，保留原始候选计数及忽略/修改记录；没有完整范围复核证据时不能宣布整段正常。 |
| 演示 | 所有页面、图表、事项、详情和助手上下文持续显示“合成演示”；与真实来源隔离，不能跳转到假用户或真实文件执行复核。 |
| 读取失败 | 显示失败范围、重试入口和已有快照时间；失败不变成空列表或零值。 |
| 不可比 / 无法判断 | 两期事实值可分别查看，变化结论及百分比为“— + 原因”；提供核对批次和覆盖的下一步。 |

## 9. 需用户确认的建议边界

以下均未实施，不能作为已批准规则：

- 巡检首页优先及运营视图降为次级；默认 7 天与紧邻等长对照。
- 事项第一版只用描述性变化及明确数据缺口，是否加入自动阈值、何时使用“异常”称呼及其规则。
- 候选跨边界计数、重复记录/扫描合并、跨记录重复暴露处理、有效分析区间与可评估区间定义。
- 覆盖最低要求、最少有效小时、变化幅度、优先级和工作流状态；所有数值阈值均待确认。
- 记录查询与真实用户映射接入顺序、批量扫描能力、助手可调用能力及是否允许写入事项状态。

建议第一阶段先做来源/覆盖透明的记录级描述性巡检；真实用户映射、完整分母和可比性验证齐备后，再开放用户级聚合及自动事项。具体阶段安排由用户确认。

## 10. 十条可验收场景（未来实施后使用，本轮不执行）

1. **未接数据库首次打开**：来源明确未连接，用户数及总体候选密度为“—”；不产生用户榜单。可打开真实本地单份工具，且页面不声称该记录属于某用户。
2. **有记录但尚未扫描**：显示已知记录及未扫描状态，候选数和密度不显示 0；扫描能力未接入时不出现可执行的虚假批量按钮。
3. **有效分析完成且确实无候选**：仅在有效小时已知且大于 0 时显示 0 候选和 0 密度，附覆盖；缺失、零或未知有效小时均显示“—”，不写“正常”。
4. **当前期与对照期数据规模不同**：每条事项同时展示类型、范围、两期日期、原始量、密度、有效小时/覆盖、用户归属、可比性、证据与下一步；不能只凭原始量增加判定异常。
5. **算法或参数不可比**：切换到不同版本、输入、时间模式或有效区间定义后，详情列出差异，增减结论不可用；历史重复批次不叠加计数，第一版不生成未经确认的异常等级。
6. **每日趋势有缺失与零值**：未扫描日、缺失日画空隙，已分析且无候选日画零点；数据表与悬停同时提供数量、有效小时、密度与覆盖，不把 CSV 首尾跨度变成有效分析小时。
7. **无用户归属及部分归属**：无映射时只允许记录级下钻，涉及用户显示未知；部分映射时分别展示已关联用户和未关联记录，不输出假用户排序，也不允许仅凭 URL user_id 加载波形。
8. **完成一次真实波形复核再返回**：记录、批次、候选区间正确，复核后返回恢复全部筛选、对照期、排序及列表位置，更新复核状态但保留原始扫描计数；失效上下文明确报错而不切换目标。
9. **演示、快速切换与读取失败**：演示在首页/详情持续标识且不能复核假记录；切回真实来源、快速切换范围后旧请求无权覆盖新结果。读取失败显示重试及失败范围，不伪装为空态或零值；移动端同样可查看事项全部字段及图表数据表。
10. **受限助手与未知规则**：未接助手时展示待接入；接入后的回答仅解释当前授权上下文并引用证据，缺分母、归属或可比性时说明限制。没有确认的阈值不生成异常结论，不自动扫描、确认候选或执行任意数据库查询。
