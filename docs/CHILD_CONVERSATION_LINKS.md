# Persistent child conversation links

This Explorer change restores the same verified child branch across renderer origins, window changes and backend restarts. A link is derived from existing committed native fork reservations, the registered child session and permanent session ownership. It is not a browser localStorage grant and cannot point at an arbitrary supplied Somnus conversation ID. Existing native child forks can therefore be found without rewriting their histories or trusting old browser caches. Unproven standalone chats remain intact and unassociated.

The desktop host reads GET /api/assistant/conversations/{parentCid}/child-conversations?turn_id=...&child_id=.... child_id can be a registered native child session ID or its NativeSubagentTree SHA256 step ID. Native desktop proof is required; untrusted origins remain rejected. The response preserves the selected source turn's route and returns explicit linked/none/pending/deleted/archived/source_deleted/source_archived/source_scope_changed/target_scope_changed/unverified status with can_open and can_send. Lookup never runs a model, creates a fork, starts a turn or grants a tool permission. A failed lookup is not none.

For a child-pane fork request, an existing verified link is returned with existing=true, and the host must open that conversation without calling the native fork engine again. A concurrent uncommitted reservation blocks a duplicate fork until it commits, aborts or expires. Main-message native forks continue to support independent branches. Removed or archived targets are not silently replaced, and all original messages remain preserved. Continuing a linked child still goes through the normal new-turn permissions, current scope checks and real runtime route.

No arbitrary link PUT or legacy localStorage migration endpoint is provided. The server reconstructs only associations it can prove from committed fork evidence. Remote control is intentionally outside this Explorer task and outside the requested feature comparison scope. Existing remote data gateway connections are separate capabilities and are retained.
